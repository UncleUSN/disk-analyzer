# Анализатор диска

Программа для Windows, которая ищет **крупные файлы, которыми давно не пользовались** и которые, скорее всего, можно удалить. Она показывает список. Решение всегда остаётся за вами.

Программа **ничего не удаляет и не изменяет**. Она только читает имена, размеры, даты и атрибуты. Содержимое файлов не открывается.

Окно на русском языке. Подходит, если вы только начинаете разбираться с компьютером и с кодом: ниже написано, что именно она делает и как её собрать.

## Что попадает в список

Файл показывается, только если выполнены **все** условия сразу.

### 1. Давно не использовался

По умолчанию — больше **365 дней**. Срок можно изменить в окне (от 1 до 3650 дней).

«Последнее использование» — это **более поздняя** из двух дат:

- когда файл последний раз открывали (`LastAccessTime`);
- когда его последний раз изменяли (`LastWriteTime`).

Срок считается как 24 часа, а не как календарная дата. Ровно 365 дней назад файл ещё **не** считается достаточно старым: нужно больше, чем указанное число дней.

### 2. Это не системный файл

Пропускаются:

- файлы с атрибутом «Системный»;
- программы и библиотеки с расширениями `.exe`, `.dll`, `.sys`, `.msi`, `.drv` — **в любой папке**;
- файлы `pagefile.sys`, `hiberfil.sys`, `swapfile.sys` и файлы, имя которых начинается с `DumpStack`;
- каталоги в корне диска: `Windows`, `ProgramData`, `System Volume Information`, `$Recycle.Bin`, `$WinREAgent`, `Recovery`, `Boot`, `EFI`, `PerfLogs`;
- вложенные каталоги профиля: `AppData\Local\Programs`, `AppData\Local\Microsoft`, `AppData\Local\Packages`.

Папка `Windows.old` **не** исключается: в ней часто лежат большие остатки прошлой установки Windows.

Список папок, имён и расширений лежит в файле `exclusions.json` рядом с программой. Его можно править в блокноте. Следующее сканирование подхватит изменения. Комментарии `//` в этом файле разрешены. Атрибут «Системный» отключить нельзя: такие файлы пропускаются всегда.

### 3. Достаточно большой

По умолчанию — не меньше **50 МБ**. Размер можно изменить (от 1 до 10240 МБ).

1 МБ здесь — это 1024 × 1024 байт, как в проводнике Windows.

## Папки Program Files

`C:\Program Files` и `C:\Program Files (x86)` **просматриваются**.

Внутри них в список могут попасть крупные старые файлы, которые не являются программами: кэш, журналы, архивы, данные установщиков. Сами программы по-прежнему скрыты: пропускаются `.exe`, `.dll`, `.sys`, `.msi`, `.drv` и файлы с атрибутом «Системный».

## Время последнего доступа

На Windows 10 и 11 обновление даты последнего доступа **обычно выключено**. Система так делает специально, чтобы диск меньше изнашивался. Проверить можно одной из команд (программа сама смотрит то же самое и настройку не меняет):

```text
fsutil behavior query disablelastaccess
```

или параметр реестра `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\NtfsDisableLastAccessUpdate`.

Смысл имеют младшие два бита числа:

| Значение | Что это значит |
| --- | --- |
| 0 | обновления включены (так решил пользователь) |
| 1 | обновления выключены (так решил пользователь) |
| 2 | обновления выключены (так решила система, обычный случай) |
| 3 | обновления включены (так решила система) |

Старший бит `0x80000000` встречается у системной настройки и на эти два бита не влияет. Например, `2147483650` (`0x80000002`) — это режим 2, обновления выключены.

Если обновления выключены, дата доступа часто остаётся старой. Тогда «последнее использование» фактически совпадает с датой изменения. Файл, который недавно открывали и не сохраняли, может попасть в список как давно неиспользуемый. В окне в этом случае показывается жёлтое предупреждение. Это нормально для обычной Windows 10/11.

Программа эту настройку Windows не меняет. Включать обновление даты доступа не обязательно. Если очень нужно, чтобы дата открытия тоже учитывалась, администратор может выполнить `fsutil behavior set disablelastaccess 0` и перезагрузить компьютер. На скорость диска это может немного повлиять.

## Как пользоваться

1. Запустите `DiskAnalyzer.exe`.
2. Оставьте диск `C:\` или выберите другой диск, папку, введите путь или перетащите папку в поле.
3. При необходимости поменяйте срок и минимальный размер.
4. Нажмите **Сканировать**. Просмотр идёт в фоне, окно не зависает. Кнопка **Отмена** останавливает просмотр; уже найденные файлы остаются в таблице.
5. Таблицу можно сортировать щелчком по заголовку. Под таблицей показан общий размер найденных файлов.
6. Поле «Фильтр» и список «Расширение» сужают таблицу. Общий размер при этом пересчитывается по видимым строкам.
7. Выберите строку и нажмите **Открыть папку** (или дважды щёлкните строку). Откроется проводник, и файл в нём будет выделен.
8. **Экспорт CSV** сохраняет то, что сейчас видно в таблице (с учётом фильтра). Файл в кодировке UTF-8, разделитель — точка с запятой, так его открывает Excel на русской Windows. Колонка «Размер (байт)» — точное число байт.

Первый просмотр всего диска `C:\` может занять несколько минут: программа обходит папки, а не читает секретный каталог диска. Чужие папки без доступа пропускаются. Ссылки и соединения папок (junction) не преследуются, чтобы не зациклиться и не посчитать один файл дважды. Длинные пути тоже поддерживаются.

## Права администратора

Программа работает **без прав администратора**.

Без них Windows не пускает в часть папок: чужие профили, `System Volume Information`, некоторые каталоги внутри `Program Files`. Они будут пропущены, в строке состояния видно, сколько папок пропущено.

Если запустить программу **от имени администратора**, она увидит больше файлов. Удалять она всё равно ничего не будет.

## Как устроен проект

| Папка | Зачем |
| --- | --- |
| `src/DiskAnalyzer.Core` | Правила и обход папок, без окон. Это проверяют тесты. |
| `src/DiskAnalyzer.App` | Окно программы (WPF). |
| `tests/DiskAnalyzer.Core.Tests` | Тесты срока, размера и исключений. |
| `config/exclusions.json` | Какие папки, имена и расширения пропускать. |
| `scripts/build.ps1` | Сборка, тесты и публикация одного exe. |

Язык — C#, платформа — .NET 8, окно — WPF.

## Как собрать и запустить на Windows

Нужна 64-разрядная Windows 10 или новее.

1. Установите **.NET 8 SDK**: [https://dotnet.microsoft.com/download/dotnet/8.0](https://dotnet.microsoft.com/download/dotnet/8.0). Нужен именно SDK, не только Runtime: SDK умеет собирать программу.
2. Откройте PowerShell в папке репозитория и проверьте установку:

   ```powershell
   dotnet --version
   ```

   Должна быть версия `8.x`.

3. Соберите программу, прогоните тесты и получите один exe:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
   ```

   Скрипт выполняет сборку, тесты и публикацию:

   ```text
   dotnet publish -r win-x64 --self-contained true -p:PublishSingleFile=true
   ```

4. Готовые файлы:

   - `artifacts\publish\DiskAnalyzer.exe` — программа со всем необходимым внутри, отдельно ставить .NET на компьютер пользователя не нужно;
   - `artifacts\publish\exclusions.json` — правила исключений рядом с exe.

5. Запустите `DiskAnalyzer.exe` двойным щелчком.

Первый запуск одного большого exe может занять несколько секунд: Windows распаковывает его во временную папку.

Открыть проект в Visual Studio 2022 тоже можно: файл `DiskAnalyzer.sln`, запускаемый проект — `DiskAnalyzer.App`, клавиша F5. Для обычного запуска из Visual Studio на компьютере должен стоять .NET 8 SDK. Готовый exe из папки `artifacts` от SDK уже не зависит.

Если Windows SmartScreen напишет, что издатель неизвестен, это из-за того, что exe не подписан цифровой подписью. Нажмите «Подробнее», затем «Выполнить в любом случае».

## Как скачать готовый exe из GitHub Actions

Собирать проект у себя не обязательно. Готовый exe появляется в результатах сборки на GitHub.

1. Откройте [Actions репозитория](https://github.com/UncleUSN/disk-analyzer/actions).
2. Выберите последний **успешный** запуск workflow **CI** (зелёная галочка). Сборка идёт на `windows-latest`: компиляция, тесты и публикация exe.
3. Внизу страницы блок **Artifacts**. Скачайте **DiskAnalyzer-win-x64**.
4. Распакуйте zip. Внутри `DiskAnalyzer.exe` и `exclusions.json`. Держите их в одной папке.
5. Запустите exe. Если `exclusions.json` потерялся, программа один раз попробует записать правила по умолчанию рядом с собой и в любом случае знает встроенную копию.

Артефакты GitHub хранятся ограниченное время (обычно 90 дней). Если старый файл уже исчез, откройте более свежий успешный запуск или запустите workflow вручную кнопкой **Run workflow**, если она доступна.

## Тесты

Проверяются срок (включая границу «ровно N дней» и выбор более поздней из двух дат), минимальный размер, атрибут «Системный», расширения программ, системные папки и то, что `Program Files` и `Program Files (x86)` в список исключений не входят. Отдельный тест обходит настоящую временную папку и проверяет, что байты файла и дата изменения после сканирования те же.

Локально:

```powershell
dotnet test DiskAnalyzer.sln -c Release
```
